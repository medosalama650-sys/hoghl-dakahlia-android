# خطة الإصدار الآمن — شغل الدقهلية

## التغييرات في فرع التطوير
- تهدئة إعادة رسم قائمة الوظائف أثناء إدخال حدود الراتب.
- عدم إسقاط `ownerUid` بصمت عند رفض Firestore لعملية إنشاء إعلان من حساب صاحب عمل؛ يظهر خطأ واضح بدل إنشاء إعلان غير مربوط بالمالك.
- تحسين مؤشر التركيز بلوحة المفاتيح واحترام إعداد تقليل الحركة في الجهاز.
- تغيير إصدار Service Worker حتى يتم التخلص من ملفات الواجهة القديمة المخزنة عند تحميل الإصدار الجديد.
- إضافة فحوصات ثابتة آلية عبر GitHub Actions.

## قبل دمج الإصدار ونشره
1. افتح الموقع من Chrome على الهاتف وجرب البحث والراتب والمنطقة والتصنيف.
2. أنشئ حساب صاحب عمل تجريبيًا، ثم جرّب نشر إعلان والتأكد من حفظ `ownerUid`.
3. جرّب حسابًا لا يملك صلاحيات الإدارة وتأكد أنه لا يستطيع اعتماد إعلان أو تمييزه.
4. اختبر التقديم عبر واتساب واستعادة كلمة المرور.
5. اختبر تحديث الموقع بعد حذف بيانات الموقع المؤقتة أو إعادة تحميله، وتأكد من عدم ظهور نسخة قديمة.
6. شغّل فحوصات Firestore Rules في Firebase Emulator Suite قبل تغيير القواعد المنشورة.
7. راجع تكلفة القراءات؛ تقسيم نتائج الوظائف إلى صفحات يحتاج تصميمًا متوافقًا مع البحث والترتيب والقرب من الموقع قبل تفعيله.

## ملاحظات أمان مهمة
- لا تعتبر إخفاء عناصر الإدارة في الواجهة حماية؛ يجب فرض الصلاحيات في Firestore Rules أو في بيئة خادم موثوقة.
- لا تغيّر قواعد Firestore المنشورة دون اختبار إنشاء الإعلانات وملكيتها والتقديم والبلاغات على بيانات تجريبية.
- مفاتيح Firebase client config ليست بديلًا عن قواعد Firestore المقيدة. لا تضع مفاتيح خدمة أو أسرار خادم داخل ملفات الواجهة.
- طلبات التمييز الحالية ليست دليلًا على تحصيل إلكتروني؛ يجب التحقق من الدفع من مصدر موثوق قبل تفعيل أي إعلان مدفوع.
