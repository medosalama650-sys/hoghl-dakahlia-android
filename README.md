# شغل الدقهلية | منصة الوظائف الحقيقية

منصة عربية باتجاه RTL لعرض فرص العمل في المنصورة والمناطق المحيطة بها حتى خط دكرنس. الواجهة مصممة للموبايل وتدعم التثبيت كتطبيق ويب تقدمي (PWA) في المتصفحات المتوافقة.

## المميزات الموجودة في المشروع

### للباحث عن عمل
- البحث في الوظائف والتصفية حسب المنطقة والتصنيف والراتب والترتيب.
- اختصارات للتصنيفات: كاشير، مبيعات، مطاعم، سائقين، عمال، محاسبين، ودليفري.
- المناطق المستهدفة: المنصورة، أويش الحجر، البدالة، البرامون، البقلية، برق العز، بدواي، شها، طناح، ميت بدر خميس، ميت مزاح، ومحلة الدمنة.
- استبعاد الإعلانات المنتهية تلقائيًا من نتائج الوظائف.
- التقديم عبر واتساب، ومشاركة الوظائف، وفتح موقع جهة العمل على خرائط Google.
- حفظ الوظائف وتسجيل التقديم محليًا على الجهاز.
- التقديم داخل المنصة للإعلانات التي تدعم ذلك، مع متابعة حالة الطلب من لوحة صاحب العمل.
- البحث عن الوظائف القريبة بعد موافقة المستخدم على إذن الموقع، مع إمكانية اختيار المنطقة يدويًا.
- منشئ سيرة ذاتية (CV) وتجهيزها للطباعة أو الحفظ PDF؛ بيانات السيرة تُجهّز محليًا ولا تُرفع إلى Firebase.
- الإبلاغ عن الإعلانات، ودليل الشركات وأصحاب العمل، وتفضيلات تنبيهات المتصفح أثناء فتح الموقع.
- واجهة عربية RTL، وملف Manifest، وأيقونة، وService Worker لدعم التثبيت والتخزين المؤقت.

### لصاحب العمل والإدارة
- تسجيل حساب صاحب العمل والدخول بالبريد الإلكتروني وكلمة المرور عبر Firebase Authentication.
- استعادة كلمة المرور بالبريد الإلكتروني.
- عرض إعلانات صاحب العمل وتعديلها وإغلاقها أو حذفها وفق قواعد Firestore.
- متابعة طلبات التقديم داخل المنصة وتحديث حالتها والتواصل مع المتقدم عبر واتساب عند توفر رقم.
- لوحة إدارة لمراجعة الإعلانات والبلاغات، وإحصاءات وتصدير CSV.
- دعم حالات الإعلان المميز والتحقق من جهة العمل في الواجهة. تمييز الإعلان يُفعّل يدويًا بعد تأكيد الدفع؛ لا توجد بوابة دفع إلكترونية مدمجة.

## الملفات الأساسية

- `index.html` — الواجهة الرئيسية ومنطق البحث والوظائف والتقديم ولوحة الإدارة.
- `employer.html` — حساب صاحب العمل وإدارة الإعلانات وطلبات التقديم.
- `manifest.json` — إعدادات تثبيت الموقع كتطبيق ويب.
- `icon.svg` — أيقونة الموقع.
- `sw.js` — التخزين المؤقت الأساسي ودعم فتح الواجهة عند انقطاع الاتصال.
- `firestore.rules` — قواعد Firestore المقترحة؛ رفع الملف إلى GitHub لا ينشر القواعد إلى Firebase تلقائيًا.
- `scripts/check-app.mjs` — فحوصات ثابتة للوظائف الأساسية.
- `.github/workflows/validate.yml` — تشغيل الفحوصات تلقائيًا عبر GitHub Actions.
- `docs/RELEASE-CHECKLIST.md` — قائمة تحقق قبل الإصدار.

## إعداد Firebase

1. استخدم مشروع Firebase تملك صلاحية إدارته، وتأكد أن إعدادات العميل في الواجهة تخص المشروع الصحيح.
2. فعّل تسجيل الدخول بالبريد الإلكتروني وكلمة المرور، وتأكد من تفعيل تسجيل الدخول المجهول إذا كانت الواجهة الرئيسية تعتمد عليه.
3. أنشئ Cloud Firestore وراجع قواعد `firestore.rules`.
4. اختبر الصلاحيات على بيانات تجريبية باستخدام Firebase Emulator Suite قبل نشر أي تغيير.
5. انشر قواعد Firestore من Firebase Console أو Firebase CLI بشكل مستقل عن نشر ملفات الموقع.
6. اختبر أن المستخدم لا يستطيع تعديل إعلانات غيره أو تنفيذ إجراءات الإدارة دون صلاحية مناسبة.

**مهم:** إعدادات Firebase client config ليست بديلًا عن قواعد Firestore الآمنة. لا تضع كلمات مرور أو مفاتيح خدمة أو أسرار خادم داخل ملفات الواجهة أو المستودع. لا تستخدم قواعد قراءة وكتابة عامة.

## النشر

### GitHub Pages
من إعدادات المستودع افتح **Settings → Pages**، واختر الفرع `main` والمجلد الجذر إذا كانت هذه هي بنية النشر. بعد النشر اختبر الرابط الفعلي من الهاتف وتأكد أن ملفات الصفحة التابعة تُحمّل من نفس المسار. الرابط المتوقع لهذا المستودع إذا فُعّل GitHub Pages هو:

https://medosalama650-sys.github.io/hoghl-dakahlia-android/

وجود الرابط المتوقع هنا لا يؤكد وحده أن GitHub Pages مفعّل أو أن النشر نجح.

### تطبيق Android
يمكن تغليف رابط الموقع داخل APK بأداة خارجية. بعد كل تحديث اختبر فتح واتساب والروابط الخارجية وتسجيل الدخول على هاتف فعلي. تحديث ملفات الموقع لا يحدّث تلقائيًا كل نسخة APK قديمة إذا كانت النسخة لا تفتح الموقع المنشور مباشرة.

## الفحوصات قبل تسليم أو إصدار نسخة

- راجع نتيجة GitHub Actions.
- أنشئ حساب صاحب عمل تجريبيًا وجرّب الدخول واستعادة كلمة المرور.
- أنشئ إعلانًا وتأكد من ربطه بمالك الحساب، ثم جرّب التعديل والإغلاق.
- اختبر التقديم عبر واتساب والتقديم داخل المنصة كلٌّ على حدة.
- اختبر البلاغات وصلاحيات الإدارة بحساب غير إداري.
- اختبر النسخة المنشورة على Android، بما فيها تحديث الملفات المخزنة مؤقتًا.
- اختبر قواعد Firestore في بيئة تجريبية؛ الفحوصات الثابتة وحدها لا تثبت نجاح تدفقات Firebase كاملة.

## حدود مهمة

- التقديم عبر واتساب يفتح محادثة خارجية، ولا يظهر تلقائيًا في قائمة طلبات التقديم الداخلية.
- طلب تمييز إعلان لا يعني أن الدفع الإلكتروني تم؛ تفعيل التمييز يعتمد على إجراء إداري يدوي.
- تنبيهات المتصفح ليست نظام إشعارات خلفية مضمونًا بعد إغلاق الموقع.
- لا تعتبر ميزة مكتملة نهائيًا قبل اختبارها على النسخة المنشورة وحساب Firebase المستخدم للإنتاج.
